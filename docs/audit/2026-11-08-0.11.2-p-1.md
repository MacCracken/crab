# crab 0.11.2 — the P(-1) audit

**Audited:** crab 0.11.1 (`src/` 13,500 lines, about 7,050 of them code), on cyrius 6.7.18, agnos 1.57.17 and
aethersafha 0.17.7. **What an operator sees:** CHANGELOG 0.11.2. **The previous audit:**
[`2026-08-31-audit.md`](2026-08-31-audit.md).

- **The worst class is an action landing on something the operator did not name.** A cancel deleted a finished
  file (H1). A prompt or rename sheet stayed armed while a transfer rewrote the rows it described (H6). A refused
  verb replaced the running queue, then ran anyway (H7). A held key moved the selection under an open menu (H8).
  None of these was a memory error.
- **Two losses of the only copy.** A Replace unlinked the destination before knowing the source could be opened
  (H2), and a stepped move unlinked its source without asking whether the close had succeeded (H4).
- **Memory safety held.** No buffer overflow in crab's own code: every fixed buffer in `src/` was tabulated with
  every writer. The image and EXIF parsers are sound. The one hang (H9) was a loop exit in the diagnostic composer.
- **Two record corrections.** agnos has had `AO_EXCL` since 1.56.56, which `crab_fs_open_w`, `state.md` and the
  roadmap denied, and "focusing a pane by its header does not work" is false.

## Method

P(-1) as the stack defines it: cleanliness, a benchmark baseline, review by surface, the security audit, tests from
the findings, post-review benchmarks.

1. **Six read-only adversarial lenses, one per surface**, each told to enumerate every site rather than grep for
   remembered shapes, to treat comments as claims, and to prove findings with a compiled probe where the code can
   run on the host:
   - A: the write layer and data loss;
   - B: every parser of bytes crab did not author;
   - C: strings, paths, names and every fixed buffer;
   - D: the event loop and the input state machine;
   - E: the render path and hit testing;
   - F: memory over a long session, hot paths, what is worth optimizing.
2. **Every finding was read against the code before it was fixed**, and the probe re-run where one existed. Several
   were found independently by two or three lenses (H1 by A, C and D; H6 by A, C and D; H7 by A, C and D; H9 by B
   and C; M16 by B, E and F), which is the strongest confirmation the method offers.
3. **Every repair that can be reached from a host test has a mutation-checked test.** The repair was undone in a
   scratch copy and a suite was seen to go red: 53 mutants, all killed, after one test that could not see its own
   fix (H4c) was corrected. Fuzz gained a differential overread check, and all three `len` bounds that had survived
   a planted removal now go red. `tests/hardening.tcyr` holds these.
4. **What cannot be run on the host was lifted out of the `#ifdef` as a predicate** where that was the honest shape
   (`crab_relist_voids`, `crab_frame_now`, `crab_ov_key_after`, `crab_mb_open_first`, `crab_drag_marked`,
   `crab_pointer_at_edge`, `crab_sel_step`, `crab_queue_start`). The wiring stays agnos-only and is covered by the
   QEMU harnesses, not by a host test, and the table below says which is which.

## Rejected

Each was investigated and dropped, or disproved by a probe:
- copy onto self truncating the source (the exclusive open refuses it); `mv a a/b` as data loss (the kernels refuse it);
  a NULL `chitra_err_code` (48,000 mutated decodes); a FIFO named `x.png` hanging the read; overflow in
  `crab_del_prompt`; pixels drawn after a slot was reclaimed; a per-frame global-heap leak (24 view and chrome
  combinations, 0 B each); a divide by zero in layout (109,824 frames over widths 1..1000 and heights 1..220).

## Checked and sound

- **Every fixed buffer in `src/`**, with every writer. The op record, the walk stack, and the place, volume, thumbnail
  and preview layouts: no overlap, none short.
- **`crab_img_dims` and the JPEG walk**: every read bounded, marker lengths of 0 and 1 refused, the walk advances.
  **EXIF**: offsets checked at the absolute address, entries capped, a self-pointing IFD bounded.
  **`crab_thumb_scale`**: an exhaustive sweep of 1..300 × 1..300 plus extremes, no overread, no empty box.
- **All 77 `alloc` sites** classified; **all six** divisors in the parsers non-zero; every `crab_hit` read guards row -1.
- `CRAB_REC_TYPE`'s 22 readers agree on what a link is; the render path does not call up into `app.cyr`.

## Benchmarks

`tests/crab.bcyr` covers the sort, which this work did not touch: 451.9 µs at 1,024 entries before and 440.2 µs after, within this host's noise.
The repairs that change cost change how often a frame is drawn rather than how long one takes, so they are stated
as counts: a key tap is one frame, not two; a 1,024-entry stat drain is 5 frames, not 32; a marked copy of N files
re-reads the panes once, not N times.

## On the target

QEMU, agnos 1.57.17, aethersafha 0.17.7, the DCE agnos binary (`dbfc15f9…`). All 13 crab harnesses ran: button, columns,
face, go, h1, listing-cap, pointer, preview, shift and symlink PASS; resize PARTIAL at its QEMU ceiling; door and drop's
second arm UNMEASURED, and identically so on 0.11.1's binary on the same kernel, so they are limits of those harnesses.
A scratch harness covered what none of them reaches: the collision prompt (asked once, stray keys spent, `s` resumes,
the file intact on disk), a delete prompt withdrawn when a transfer ends, and a held key under the menu bar. PASS.

and M12's refusal. Nothing has run on real hardware.
